A day in the life of a Professional Services Cloud Architect at Amazon Web Services

2023年10月20日·6 分鐘

A day in the life of a Professional Services Cloud Architect at Amazon Web Services #

Photo by Hunters Race on Unsplash

I’d like to share my previous experience working as a Cloud Architect at Amazon Web Services (AWS) Professional Services Team.

Honestly, before joining AWS, I didn’t even know this team existed XD And even some friends of mine who also work in the IT industry hadn’t heard of it before, so I thought it would be beneficial to write an article about it.

What is Professional Services? #

Professional Services, or ProServ for short, is essentially IT consulting. When you think of consulting, you might immediately think of the ‘Big Four’ companies - Deloitte, KPMG, PwC and EY. They are not only the Big Four accounting/audit firms, but also leaders in the consulting industry.

So, what does ProServ usually do? In simple terms, let’s say there’s an online bookstore. Their existing IT infrastructure is in their physical data centre, like on-premises servers and load balancers.

However, due to the online bookstore’s growing business, the physical infrastructure can’t meet their needs anymore. Instead of buying more new hardware, they want to move to the cloud (PS: This is actually the real story of why Amazon later established Amazon Web Services XD).

The online bookstore heard that AWS is a great cloud service platform. Still, their in-house IT staff doesn’t have sufficient cloud expertise and knowledge to design their solution architecture on the AWS Cloud and do the migration by themself . So they decide to hire som professionals directly from AWS to help them with the migration from physical servers to cloud servers. This is where AWS ProServ comes into play.

Similarly, this online bookstore could also hire the consulting services from one of the Big Four companies (and they’re usually cheaper XD). But many large organisations, like multinational enterprises, government departments, and universities, choose AWS ProServ because we are directly affiliated with AWS. In other words, if there is any complex issues and system problems, we can rely on the internal AWS resources and reach out to the product teams for help.

What Does Professional Services do? #

ProServ’s tasks are incredibly diverse because we work on a project-by-project basis. This means that what we do depends on the projects we’re assigned XD

For example, I’ve helped plan the network architecture and firewall rules for an Australian university (one of Australia’s top eight universities in Melbourne). I’ve also conducted an internal security assessment report for a research institution in Australia. Before leaving AWS, I was involved in planning the Australian Bureau of Statistics’ internal big data platform (data lake) and creating internal tools to help them transition from old enterprise statistical analysis software to internal web applications. I’ve also done data engineering and data visualization.

The examples I’ve mentioned are very different fields within the IT industry. Usually, people won’t be experts in everything. Still, ProServ requires you to have the ability to move between various IT domains.

Day to Day Work #

ProServ’s main task is technical delivery, meaning we need to understand our customers’ requirements, plan solutions and implement them.

Senior Cloud Architects not only lead technical teams but often need to meet with senior customer executives to reach strategic consensus. Cloud Architects, in general, work with customers’ IT or developer departments, attending meetings, sprint planning, code reviews, and even giving some lectures or workshops to enhance customers’ cloud knowledge and skills.

Besides that, Cloud Architects charge by the hour. So, in a 40-hour workweek, we must report how much time we spent on Customer A, Customer B, internal meetings, and training.

Timesheets are actually the part of ProServ work I like the least. The customer-first work style ends up compressing the time I personally need to learn new technologies and grow.

Required Skills #

“Do Cloud Architects need to code?” is perhaps the most frequently asked question.

Simply put, coding isn’t necessary, but, in reality, you can’t completely avoid it. Even though current cloud services can be set up on a GUI console, there will still be times when you need to use the command line interface (CLI), Cloud Development Kit (CDK), or Software Development Kit (SDK).

With the recent popularity of Infrastructure as Code (IaC), you will need to know how to write CloudFormation (JSON or YAML) or Terraform. Not to mention, the most common programming languages for serverless services, like AWS Lambda, are Python or JavaScript/TypeScript.

But in Cloud Architect interviews, we don’t test coding or algorithms XD. Knowing a programming language roughly is sufficient (although if you’re good at coding, your work efficiency will be significantly higher).

Another common question is, “I haven’t used cloud platforms like AWS or Azure and don’t have related experience. Is that okay?”

The answer is a definite yes! Of course, having related experience is great, but it’s not a must. Everything can be learned. During interviews, we only test your basic IT knowledge, such as networking, databases, encryption, application development, security and more.

So you might ask, if none of the above skills are required, what is needed?

Surprisingly, apart from the aforementioned basic IT knowledge (after all, Cloud Architects are still a technical role), what we value the most is:

  1. Learning ability : Can you pick up a new technology or cloud service within a short time and then teach it to customers and guide them in implementing it?
  2. Consulting skills : Ultimately, Cloud Architects are technical consultants. Can you listen to the customer’s needs, plan solutions based on their requirements, lead customers to solve complex problems, and earn their trust?
  3. Can you be an Amazonian : Amazon has always been proud of its unique corporate culture. When we hire new people, we care about whether they fit into our corporate culture or not, i.e. the famous Amazon Leadership Principles interviews.

So this is how it looks like working as a Cloud Architect in AWS Professional Services.
